# 1.0.4 Changelog

> This release adds daily share limits and a daily price limit (limit-up / limit-down) to the fund
> exchange, shows how many shares your balance can afford right on the buy screen, and fixes a
> temporary wrong level display after withdrawing XP from the ATM.

## Fund Exchange

### Balance hint on the buy screen

- A new line under the share input shows **"Balance allows up to N shares"**.
- The 2% fee (minimum 1) is already included, so the number is what you can actually afford.
- The same line also shows **how many shares you may still buy / sell today**.

### Daily buy / sell share limits

- Two new options in the `market` section:
  - `dailyBuyShareLimit`: shares a player may buy per day, default **10**.
  - `dailySellShareLimit`: shares a player may sell per day, default **20**.
- The limit counts **shares, not transactions**, and all seven funds share the same quota.
  - For example, buying 5 shares of Mining and 3 of Agriculture leaves 2.
- The quota resets automatically when the game day changes, independent of the daily settlement.
- Set it to `0` to disable the limit.
- When the quota is exceeded, both chat and the machine screen say how many shares are still available.
- **Sell all** automatically stops at today's remaining quota, so it never sends a request that must fail.

### Limit-up / limit-down

- New option `dailyLimitRate`, default `0.10` (+/-10%).
- Each fund's price is kept within **last close x (1 +/- this value)** for the whole day:
  - the 5-minute price updates;
  - the opening price right after the daily settlement;
  - the composite fund derived from the six industry funds.
- It combines with the existing hard bounds (base price x 0.3 ~ x 3.0); the stricter one wins.
- Set it to `1.0` for a very wide limit (at most doubling or falling to the minimum price of 1).

## Bug fixes

### Wrong level display after withdrawing XP from the ATM

- **Symptom**: a level-0 player withdrawing 1 level saw the HUD briefly show **level 7**, then it
  corrected itself back to level 1 a moment later.
- **Cause**: in 1.21.1 the `ClientboundSetExperiencePacket` constructor is
  `(progress, totalExperience, experienceLevel)`, but the code passed
  `(progress, level, totalExperience)`, so the client treated 7 XP as the level.
- **Fix**: the packet is now sent in the correct order, so the level and XP bar update correctly
  immediately.
- The server-side data was always correct; saves and XP calculations were never affected.

## Configuration and compatibility

- The server TOML `market` section gains:
  - `dailyBuyShareLimit = 10`
  - `dailySellShareLimit = 20`
  - `dailyLimitRate = 0.10`
- **Existing config files are not overwritten automatically**: either edit these three values manually
  or delete `serverconfig/emerald_economy-server.toml` and let the server regenerate it.
- The protocol version is now **7** (the market snapshot gained today's quota fields). Clients and the
  server must be updated together, otherwise the connection is refused.
- Saves only gain the daily trade counters; old saves work as-is and start counting fresh on the next
  game day.
